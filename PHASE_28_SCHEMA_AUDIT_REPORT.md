## Integrity and migration review notes

1. Every model's declared primary key, FK scalar references, unique fields/constraints, nullable fields, defaults, DateTime fields, relation fields/delete actions, and explicit indexes is listed in Appendix A.
2. The 79 implicit referential-action declarations require an explicit migration review. Preserve existing behavior; do not blanket-convert deletes to Cascade.
3. Schema uniqueness includes login identifiers (`User.username`, nullable `User.email`, and `employeeCode`), `LessonProgress(studentId, lessonId)`, `AssignmentSubmission(assignmentId, studentId)`, `AttendanceRecord(sessionId, studentId)`, `AssessmentAttempt(assessmentId, studentId, attemptNumber)`, `AssessmentAnswer(attemptId, questionId)`, `XpTransaction(studentId, sourceType, sourceId, ruleKey)`, and `CourseCompletionRecord(studentId, courseId)`. Certificate `publicId` and `downloadToken` are unique, but the schema does not declare a uniqueness constraint for one active certificate per student/course.
4. A static relationship/index scan found 83 FK scalar field declarations without an explicit index/unique whose leftmost field is that FK. This is a candidate-review list only—not a directive to add 83 indexes. The user requests workload-based optimization; PostgreSQL `EXPLAIN (ANALYZE, BUFFERS)` and measured query frequency are unavailable until a staging target and representative dataset exist.
5. PostgreSQL creates the referenced-side primary/unique constraints, but does not automatically create indexes on every referencing FK. Existing query patterns and relation fields must be mapped to measured plans before changing the index set.
6. Prisma `DateTime` declarations must be mapped to an agreed UTC strategy. The application generally constructs JavaScript `Date` values and validates offset-bearing ISO inputs, but the stored timestamp distribution/timezone assumptions were not inspected as values and remain **UNKNOWN / NOT VERIFIED**. The read-only baseline hashes include the stored fields without disclosing them.

## Schema status

**BLOCKED for migration execution.** The PostgreSQL provider copy validates, but the checked-in datasource remains SQLite; there is no migration history or target; the live schema/data baseline and timezone/data compatibility are unknown. Do not switch the checked-in provider or run a migration until the source/database access and PostgreSQL target are explicitly approved.
