فاز ۱۹ — اتوماسیون و موتور گردش‌کار

گزارش پیاده‌سازی، چرخه انتشار نسخه‌ها، نتایج اعتبارسنجی و محدودیت‌های شناخته‌شده

وضعیت: زیرساخت اصلی پیاده‌سازی شدهارزیابی: هنوز آماده بهره‌برداری کامل در محیط تولید نیستدامنه: توسعه درون LMS موجود
نکته مهم: فاز ۱۹ قابلیت پایه گردش‌کار را پیاده‌سازی می‌کند، اما به‌دلیل نبود زمان‌بند/worker پیکربندی‌شده، migration تولید بازبینی‌شده و پوشش کامل تولیدکنندگان رویداد، این تحویل به‌معنای آمادگی کامل برای production نیست. برای ادامه، Phase 20 آغاز نشده است.

خلاصه اجرا

این قابلیت به LMS موجود EnglishBridge افزوده شده و جایگزین یا بازسازی برنامه نیست. URL، backend، پایگاه‌داده، حساب‌ها، نشست‌ها و سوابق یادگیری موجود حفظ شده‌اند. رویدادها، گردش‌کارها، نسخه‌ها، اجراها، گام‌ها، تأییدها و کلیدهای idempotency به‌صورت سازمان‌محور در پایگاه‌داده ذخیره می‌شوند.

ساخت و انتشار امن

تعریف محدود و اعتبارسنجی‌شده؛ بدون اجرای کد دلخواه؛ نسخه‌های منتشرشده immutable و دارای checksum.

صف و بازیابی

رویداد و اجرای پایدار، مکث قابل‌بازیابی، retry محدود، قفل‌های منقضی و جلوگیری از اجرای تکراری.

کنترل دسترسی

مجوزدهی سمت سرور و محدوده سازمانی در عملیات مدیریت، اجرا و تأیید؛ دسترسی دانش‌آموز رد می‌شود.

یکپارچگی موجود

اعلان درون‌برنامه‌ای از Communication Hub و پیشنهاد یادگیری از مدل توصیه‌گر موجود استفاده می‌کنند.

قابلیت‌های تحویل‌شده

  • رویدادهای گردش‌کار، تعریف‌ها و نسخه‌ها، run history، تاریخچه گام‌ها، وضعیت انتظار، تأیید انسانی و رکوردهای idempotency با محدوده سازمانی.
  • Event bus سمت سرور با فهرست مجاز رویدادها، کلیدهای idempotency سازمان‌محور و پالایش داده‌های حساس از metadata.
  • ارزیاب شرط ایمن با گروه‌های AND/OR و فیلدها/operatorهای ثابت؛ بدون کد یا expression دلخواه.
  • مرکز مدیریتی واکنش‌گرا در /admin/automation شامل نمای کلی، گردش‌کارها، الگوها، اجراها و تأییدها.
  • ذخیره draft، شبیه‌سازی بدون اثر جانبی، انتشار، pause، ساخت نسخه جدید، مشاهده خلاصه اجرا و پذیرش/رد تأیید.
  • APIهای حفاظت‌شده برای مدیریت، اجرای دستی، شبیه‌سازی، تأییدها و worker داخلی.
  • سرویس‌های مشخص در سمت سرور برای صف/زمان‌بند، audit، approval، run tracking، rate limiting، simulation، rule/condition/action، retry و loop protection.

رویدادها و محرک‌ها

محرک‌های اجرایی فعلی: رویداد LMS و اجرای دستی مجاز. در زمان حاضر، تنها LESSON_COMPLETED به‌طور عادی به event bus متصل است؛ رویداد MANUAL_TRIGGERED نیز برای اجرای دستی داخلی استفاده می‌شود. نام‌های دیگری مانند حضور، ارزیابی، gamification، گواهی و ارتباطات در catalog تعریف شده‌اند، اما وجود نام در catalog به معنی اتصال producer نیست.

رویداد تکمیل درس پس از تراکنش تکمیل موجود به‌صورت best-effort ثبت می‌شود. درخواست تکمیل درس اجرای گردش‌کار را هم‌زمان انجام نمی‌دهد؛ اجرای workflow با worker جداگانه صورت می‌گیرد.

ویرایش، نسخه‌بندی و چرخه انتشار

ویرایش گردش‌کار منتشرشده یک نسخه draft جدید می‌سازد و نسخه منتشرشده قبلی را فعال نگه می‌دارد. انتشار draft جدید، نسخه فعال را جابه‌جا می‌کند؛ runهای قبلی به نسخه‌ای که با آن اجرا شده‌اند متصل می‌مانند و snapshotهای منتشرشده checksum دارند.

تأیید API روی build تولید: ورود مدیر 200، ساخت draft 201، انتشار 200، ساخت نسخه دوم 200، حفظ وضعیت کلی Published با نسخه 2 و اجرای دستی 202. این تست نشان داد هنگام بازبینی نسخه جدید، نسخه منتشرشده قبلی همچنان قابل اجرا می‌ماند. داده آزمایشی پس از تست پاک شد.

اجرای دستی باید آخرین نسخه Published را انتخاب کند، نه draft در حال بازبینی. این رفتار در API با smoke test روی build تولید بررسی شد.

ایمنی، مجوزدهی و حریم داده

  • هیچ arbitrary user code یا اجرای expression آزاد در builder وجود ندارد؛ اقدامات محدود به allowlist هستند.
  • موضوع هر اقدام کاربرمحور در محدوده سازمان رویداد resolve می‌شود. کنترل مجوز سمت سرور است و endpointها برای دانش‌آموز مجاز نیستند.
  • ورودی لینک خارجی برای اقدام‌ها رد می‌شود و هیچ اقدام SSRF-capable یا webhook اجرایی در این فاز وجود ندارد.
  • رویدادهای مشتق‌شده از workflow و اقدام‌های فعلی از انتشار زنجیره‌ای بازگشتی جلوگیری می‌کنند؛ سقف صف، اندازه تعریف، تعداد گام‌ها، نرخ اجرای دستی و batch worker محدود است.
  • هیچ اقدام workflow نمره رسمی، مجوز، حساب کاربری یا گواهی را تغییر نمی‌دهد. صدور رسمی گواهی در صورت نیاز همچنان باید از مسیر approval انسانی و سرویس معتبر خودش پیروی کند.
  • محتوای اعلان فقط جایگزینی محدود {{firstName}} و {{eventType}} دارد؛ داده حساس در metadata رویداد فیلتر می‌شود.
  • ایجاد/نسخه‌بندی/انتشار، اجرای دستی، شبیه‌سازی و تصمیم تأیید در audit ثبت می‌شوند.

صف، retry و پایداری

رویدادها، wait state، approval state و تاریخچه در پایگاه‌داده ذخیره می‌شوند و با restart فرایند از بین نمی‌روند. endpoint محافظت‌شده POST /api/internal/workflow-worker batch محدود را پردازش می‌کند، waitهای سررسیدشده را ادامه می‌دهد و approvalهای منقضی را بررسی می‌کند. خطاها با backoff نمایی و حداکثر پنج تلاش مدیریت می‌شوند؛ قفل پردازش قدیمی پس از پنج دقیقه قابل‌بازیابی است.

نیازمندی deployment: باید secret سمت سرور WORKFLOW_WORKER_SECRET با حداقل ۳۲ کاراکتر تصادفی تنظیم و endpoint از یک scheduler مورداعتماد فراخوانی شود. در محیط فعلی scheduler یا worker دائمی پیکربندی نشده است؛ تا زمان فراهم‌کردن آن، کارهای صف‌شده اجرا نمی‌شوند.

تضمین exactly-once برای پذیرش provider بیرونی ادعا نمی‌شود. در صورت crash پس از پذیرش بیرونی و پیش از تکمیل ثبت محلی، reconciliation وابسته به provider لازم است. در این فاز هیچ adapter اقدام خارجی ارائه نشده است.

مدل داده و rollout

مدل‌های Prisma افزوده‌شده: WorkflowEvent، Workflow، WorkflowVersion، WorkflowRun، WorkflowRunStep، WorkflowApproval و WorkflowIdempotencyRecord. جداول محلی با prisma db push افزوده شدند و جداول موجود reset نشدند.

مخزن فعلی migration history بازبینی‌شده ندارد؛ rollout تولید نیازمند backup، تولید و بازبینی migration رسمی و برنامه استقرار روی پایگاه‌داده تولید است. db push محلی جایگزین migration تولیدی نیست.

محدودیت‌ها و کارهای لازم پیش از بهره‌برداری کامل

  1. اتصال producer سمت سرور برای رویدادهای catalogشده به سرویس‌های متناظر LMS؛ فعلاً فقط تکمیل درس و اجرای دستی قابل استفاده‌اند.
  2. پیکربندی scheduler مورداعتماد و secret سمت سرور برای اجرای مداوم صف.
  3. ایجاد و بازبینی migration تولید و اجرای rollout پس از backup.
  4. اضافه‌کردن triggerهای زمانی/تقویمی، webhook، import و زمان‌بندی مبتنی بر timezone در صورت نیاز؛ اکنون موجود نیستند.
  5. توسعه adapterهای اضافی با کنترل‌های جداگانه؛ XP، نمره، گواهی، enrollment، ایمیل/SMS/push مستقیم، webhook و mascot action پیاده‌سازی نشده‌اند.
  6. الگوها در UI presetهای draft بازبینی‌شده‌اند، نه رکوردهای پایدار template با lifecycle مستقل.
  7. builder برای مدیران مجاز است؛ مدیریت/نمایش اختصاصی معلم با محدوده گروه پیاده‌سازی نشده است.
  8. واکنش‌گرایی رابط پیاده‌سازی شده، اما تست viewport روی دستگاه واقعی و ممیزی رسمی دسترس‌پذیری انجام نشده است.
  9. تست load/soak worker انجام نشده است.
