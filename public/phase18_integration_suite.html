Enterprise Integrations — Phase 18

Integration foundation for the existing EnglishBridge web application. This is a single responsive web app; there is no native client or separate backend.

Provider connectors: NOT CONFIGURED

Transparency: No third-party credentials or vetted production adapters are installed in this workspace. The registry intentionally shows disconnected placeholders. A provider interface or demo screen must not be mistaken for a live connection.

Implemented foundation

Registry and server permissions

Organization-scoped connections

Connection metadata, safe configuration, masked credential hints, server-side permissions, audit events, and a health-test endpoint that fails honestly if an adapter is unavailable.

DISCONNECTED → configure adapter + credentials → test → enable
Provider contracts

Replaceable adapters

Interfaces cover email, SMS, web push, calendar, identity, HR directory, storage, and learning records. No vendor adapter is registered by default.

IEmailProvider · ISmsProvider · IPushProvider · ICalendarProvider · IIdentityProvider · IHRProvider
Security controls

Secrets, SSRF checks, circuit breaker

AES-GCM encrypted integration secrets (production requires INTEGRATION_SECRET_KEY), URL/IP literal checks, redirect refusal, bounded retries, and organization-scoped API client credentials.

No hard-coded production master key · No mock success health checks
Versioned API

Limited external read API

Machine credentials are hashed, expirable, rotatable and revocable. Explicit scopes and organization filters protect the currently supported read resources.

GET /api/v1/users · GET /api/v1/assessments · GET /api/v1/learning-records
Webhooks

Signed inbound/outbound mechanics

HMAC-SHA256 signatures cover timestamp and payload. Inbound requests are checked for timestamp, schema, organization and duplicate delivery ID. Outbound delivery refuses redirects.

Production caveat: no durable worker; outbound LMS event hooks are not wired across all features.
Data exchange

Dry-run user import

CSV/JSON user import validates rows before an explicit all-or-nothing commit. Invalid rows block the whole batch. Other entity imports and XLSX are not enabled.

Preview → validate → explicit commit · organization and creator checks

Available in the same web application

Administrators can inspect disconnected integration registry entries and manage supported API/webhook/import flows. Users can export an iCalendar file of existing class sessions. No synthetic calendar events are generated.
